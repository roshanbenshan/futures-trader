## 📈 实盘战绩与经验

### 核心数据（自部署以来）

- **交易胜率**: ~43%（74笔交易中32笔盈利）
- **净盈亏**: +$1.85（含手续费）
- **日内最大回撤**: 严格控制，大部分亏损<$0.50/单
- **最大单笔盈利**: +$48.70

> 💡 **43%胜率能赚钱的秘密？** 盈亏比。平均盈利单是平均亏损单的3-5倍。不要追求高胜率，追求"小亏大赚"。

### 我们踩过的坑（真实教训）

#### 🔴 教训1：追涨杀跌是亏损第一来源
> "宁可错过也不能追高杀低"

系统设计的第一原则：**做多必须等回踩支撑位，做空必须等反弹阻力位**。入场前必须问自己：这是追涨吗？这是杀跌吗？

**代码实现**：阳线实体过滤——当前K线实体长度超过ATR×0.3时，拒绝追入。

#### 🔴 教训2：手续费吃掉一半利润
74笔交易总手续费约$1.85，几乎等于总净利润。**资金少的情况下，频繁交易是慢性自杀**。

**应对**：
- 冷却机制：同一币种亏损后冷却1-6小时
- 信号门槛：评分<0.65不开仓
- 基础冷却：开仓后1小时内不再碰同币种

#### 🔴 教训3：双实例会导致数据污染
> 两个daemon同时运行，一个成交一个也记录，数据完全失真。

**应对**：启动时检测PID锁，拒绝重复实例；systemd管理单实例。

#### 🔴 教训4：不要相信标记价计算盈亏
> 标记价（markPrice）估算的盈亏和实际成交价可能有差异。**始终以订单成交均价（avgPrice）和手续费（commission）为准**。

**应对**：平仓函数直接从币安订单API获取成交均价，计入手续费后记录。

#### 🔴 教训5：方向锁定不能随便加又不能随便删
做过一次方向锁定（连续做空6次后强制转向做多），被patch误删导致亏损约$6。**代码改动必须先出清单、验证影响面、再动手**。

## 🏗 系统架构

```
┌─────────────────────────────────────────────────────┐
│                  生产环境（服务器）                     │
│                                                      │
│  data_collector.py    futures_trader.py               │
│  （WS数据收集）        （交易引擎）                      │
│       │                    │                          │
│       │   ┌──────────┐    │                          │
│       └──→│  Redis   │←───┘                          │
│           │ (缓存层)  │                                │
│           └────┬─────┘                                │
│                │                                      │
│                ↓                                      │
│         Telegram推送（盘中监测/预警/日报）              │
└─────────────────────────────────────────────────────┘
         ↑
   你/AI助手（读Redis，零HTTP，毫秒级响应）
```

### 数据流

1. **WebSocket订阅**：150+币种的15m K线、账户更新、资金费率 → 实时推入Redis
2. **交易引擎**：每30-60秒从Redis读取数据扫描 → 多因子评分 → 条件满足即开仓
3. **风控层**：±6%条件单、瀑布保护、横扫保护、连败暂停 → 全程自动运行
4. **人机协同**：AI助手通过Redis获取数据做决策，不直接调用币安API

> 🎯 **为什么用Redis当中间层？** 数据收集器和交易引擎解耦。WS断连时Redis还有缓存数据，AI读Redis比读HTTP快10倍。更重要的是——不会因为临时HTTP请求阻塞扫描周期。

## ⚙️ 快速部署

```bash
# 1. 克隆
git clone https://github.com/roshanbenshan/futures-trader.git
cd futures-trader

# 2. 一键部署（安装依赖 + systemd服务）
bash deploy/install.sh

# 3. 配置API密钥
nano .env    # 填入 BINANCE_API_KEY 和 BINANCE_API_SECRET
             # API需要：合约交易权限 + 读取权限 + 开通Internal Transfer

# 4. 启动
sudo systemctl start futures-trader
sudo systemctl status futures-trader    # 确认运行正常
```

### 依赖环境

- **Python 3.9+** — 核心运行环境
- **Redis** — 数据缓存层（内存占用<50MB）
- **pip包**: `redis`, `websockets`, `requests`, `pandas`
- **操作系统**: Ubuntu/Debian（推荐，一键部署脚本自动配置）

## 🎯 核心策略：多因子评分系统

### 选币七维度

| 因子 | 权重 | 说明 |
|------|------|------|
| 趋势方向 (MA7/MA14) | 0.22 | 均线交叉判断多空趋势 |
| RSI | 0.15 | 超买超卖区间判定 |
| 成交量确认 | 0.12 | 放量突破/缩量回调 |
| 盈亏比 (RR) | 0.15 | 预期盈利/止损距离≥3:1 |
| 波动率 (ATR) | 0.08 | 用布林带宽度确认波动率合适 |
| 资金费率 | 0.08 | 资金费率方向信号（反转指标） |
| 跨周期动量 (1h) | 0.13 | 大周期方向过滤 |
| 动量实体过滤 | 0.07 | 阳线/阴线实体超ATR×0.3时过滤 |

**总分≥0.65 才开仓**

### 三个铁律（因子设计准则）

1. **无量纲**：所有因子归一化到[0,1]区间，不依赖价格绝对值
2. **丰富度**：至少覆盖技术面、资金面、跨周期三个维度
3. **无未来函数**：不引入未来数据，所有计算基于历史已完成K线

## 🛡 风控体系（六层防御）

### 第1层：入场筛选
- **BTC断路器**：BTC ADX>50 + RSI极端值 → 大盘异常，双向封锁（只允许独立强势币绕过）
- **方向暂停**：连续亏损≥3次方向暂停12小时
- **冷却机制**：亏损<$0.10冷1h / $0.10-$0.50冷3h / >$0.50冷6h

### 第2层：资金管理
- **总余额33%均分**：3个仓位各占1/3
- **安全阀**：持仓保证金+挂单冻结>80%总余额时强制缩量
- **5x杠杆固定**：不在杠杆上冒险

### 第3层：条件单保护（±6%规则）
```
做多：SL = entry × 0.988 (-1.2% = -6%保证金)
       TP = entry × 1.012 (+1.2% = +6%保证金)
做空：SL = entry × 1.012
       TP = entry × 0.988
保底：SL = max(1.2%, ATR×0.5)
```

### 第4层：盘中监测
- 瀑布保护：价格急跌3%强制平仓
- 横扫保护：15m大阳/大阴线急速反转
- 回调跟踪止损：利润回撤达阈值自动止盈
- 反转预警：RSI+MA指标组合监测趋势反转

### 第5层：数据防护
- 成交量为0的订单拒绝记录
- 出场价≤0的假数据拒绝写入
- Redis数据与币安API每日同步验证

### 第6层：系统层
- systemd自动重启（崩溃5秒恢复）
- 双实例检测（启动时PID锁）
- 单实例守护（拒绝重复启动）
- 日志重定向到文件（双fork后stdout丢失）

## 💡 来自生产环境的建议

### 如果你要跑实盘

1. **从小资金开始**：$30-$50就够了，先跑通所有流程
2. **先看信号质量**：测试模式运行3-5天，看评分和方向判断是否合理
3. **不要暴利改参数**：最大坑——亏了就把止损放大、仓位加重。稳是第一位的
4. **手续费是最大敌人**：资金越小，手续费占比越高。宁可少做也要做精
5. **连续3天不赚钱是一个信号**：可能是市场不合适策略，不是策略有问题

### 常见问题排查

- **一直无机会** → 检查BTC断路器状态：`python3 futures_trader.py scan`看日志
- **频繁开仓又被止损** → 可能是ATR过小导致止损太窄，检查信号评分太低
- **应该开仓但没开** → 检查冷却期Redis key `cooldown:*`、资金配额是否满仓
- **数据不对** → 检查data_collector是否运行，Redis是否连接正常
